# Spec consistency

- Domain Event payload now comes exclusively from explicit design JSON `fields`. `aggregates` must identify exactly one owner and remains responsible for package routing, BuildingBlock metadata, and subscriber placement only.
- Empty `fields` render a marker event. No Aggregate instance, Entity instance, Strong ID, or snapshot is injected implicitly, and the breaking reset retains no compatibility alias, deprecated shim, legacy toggle, or dual-path fixture.
- Artifact-independent pre-generation validation traverses every known resolved semantic edge: direct named types, nested event values, known Value Objects, List, Set, generic unqualified `Array<T>`, and Map keys/values. It runs even when only `domain-subscriber` is selected.
- Field names have no safety semantics. A scalar/value field named `entity` is legal, while a resolved Entity/Aggregate type is rejected with event name, field path, and FQN for both transient and reliable events.
- The runtime `DomainEventPayloadValidator` implementation was not weakened or changed. Generated fact and marker events pass it, while direct, nested, Iterable, Map, and array Entity references remain rejected as the fallback boundary for handwritten code and unknown wrapper types.
- Public authoring documentation and the routed tactical → technical → generator-input → runtime skill path describe the same contract.

# Known limitations and risks

- Semantic array support intentionally covers only the canonical unqualified Kotlin form `Array<T>`. Qualified `kotlin.Array<T>` and primitive aliases such as `IntArray` and `LongArray` remain unsupported.
- The pre-generation check can inspect canonical nested values and cap4k-known Value Objects. Arbitrary unknown external wrappers are intentionally left to the unchanged reflective runtime guard.
- Generated/handwritten ownership still uses the established `SKIP` conflict policy. This is an ownership boundary, not a compatibility mechanism, so an existing handwritten event is not silently overwritten.
- No external-user compatibility layer was retained because cap4k currently has no external users and the confirmed change is an intentional breaking reset.
