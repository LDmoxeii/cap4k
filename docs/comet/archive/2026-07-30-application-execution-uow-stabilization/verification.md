# Spec consistency

- The implementation matches the 15 acceptance criteria in the accepted Comet contract and the new application-execution/UoW design spec.
- Command, Query, Capability, Domain Event, and Integration Event now have independent execution semantics; generic Request and built-in Saga semantics were removed from production APIs, modules, generators, starters, examples, and routed authoring guidance.
- Command execution owns REQUIRED transaction participation and automatic UoW stabilization. Nested commands join the current physical transaction and UoW coordinator, while provider `flush()` remains an optional synchronization operation rather than an independent commit or event-drain boundary.
- Domain Events are validated as immutable historical facts without Entity references. Synchronous causal processing is non-reentrant and fail-fast, ordinary local asynchronous handlers are rejected, reliable asynchronous work uses Command, and external facts use Integration Event/outbox semantics.
- Aggregate lifecycle support retains optional reflective `onCreate` and `onDeleted`, removes `onUpdate`, and folds pre-flush CREATE to REMOVE into NONE while discarding unreleased events for that root.
