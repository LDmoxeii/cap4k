# Spec consistency

- PR #149's final 2026-07-30 design requires a final post-`STABLE` assertion over Hibernate dirty/action state, pending Domain Events, and unpersisted reliable records. The original implementation stopped after the LOWEST_PRECEDENCE Spring `beforeCommit` stabilization and did not implement that final assertion.
- The repair uses Hibernate `BeforeTransactionCompletionProcess`, which runs after Spring transaction synchronizations and before database commit. It detects pending UoW intents, provider dirtiness, queued Hibernate actions, pending Domain Events, and pending Integration Event attachments, then raises `LatePersistenceMutationException` to roll back with diagnostics.
- PR #150 remains authoritative for overlapping managed-field behavior. Admission-time ID initialization, side-effect-free UoW validation, qualifier-owned exact handles, per-enricher mutation footprints, and qualifier/slot rules were preserved unchanged and passed their full test matrix.
- The proposed complete target specification replaces the stale canonical Native specification that still described the earlier explicit-flush/enrollment model. Archive will update the canonical specification under Comet's base-hash guard.

# Known limitations and risks

- The final commit-boundary assertion intentionally depends on Hibernate's `SessionImplementor`, `ActionQueue`, and `BeforeTransactionCompletionProcess`; this is consistent with the design's explicit Hibernate ownership but must be revalidated when upgrading Hibernate internals.
- Direct application bulk DML, native SQL, or manual `EntityManager.flush()` remains outside the supported contract and is not converted into a provider-neutral interception layer.
- The external transports were verified with repository tests rather than live brokers; delivery infrastructure and broker configuration remain deployment concerns.

# Conclusion

PASS. The Comet re-audit found one real PR #149 correctness defect: late persistence/event mutation after UoW stabilization could escape the coordinator and commit silently. The defect is fixed with a true Hibernate commit-boundary assertion, regression tests prove rollback and diagnostics, Query's real lazy/read-only behavior is covered, PR #150 semantics remain authoritative, owning-module suites pass, and the complete repository `check` passes.
