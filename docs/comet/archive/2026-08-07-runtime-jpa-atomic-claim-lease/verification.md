# Skipped checks

- No live production MySQL or PostgreSQL server was used. The integration tests use H2 in MySQL mode with Hibernate `create-drop`; this is real JPA transaction/concurrency coverage, not proof of every production dialect.
- The hand-written `command.sql` and `event.sql` resources were checked for mapped-column alignment but were not executed as migration scripts. Existing deployments still need an explicit schema reset/migration for `delivery_token`, `lease_until`, and the claim indexes.
- Repository-wide `./gradlew.bat check` was not required for this capability-owner slice; the relevant core, shared JPA, Command JPA, Event JPA, and both starter suites were run locally. PR CI remains the final repository-wide check.

# Spec consistency

The implementation matches the complete target specification. Command and Event use separate JPA carriers and mirrored CAS queries, while the shared `JpaOwnershipClaim`/`ReliableJpaOwnership` value contract keeps token generation, time normalization, and lease rules identical. Claims, renewals, acknowledgements, and failure transitions are conditional database updates inside `REQUIRES_NEW` transactions. Failure facts are produced through the existing safe representation and retry delay is read from the persisted policy snapshot.

# Known limitations and risks

- The SQL resources are MySQL-oriented (`AUTO_INCREMENT`, backticks, `datetime`, inline `KEY`, `ENGINE=InnoDB`, `to_days`, and table comments). PostgreSQL compatibility and vendor-specific execution plans remain outside this slice.
- The lease columns use millisecond precision while several existing timestamp columns remain second precision in the hand-written SQL. Real MySQL may therefore round boundary comparisons by up to roughly one second; H2 does not establish that production behavior.
- No ALTER/migration scripts were added. The project explicitly permits breaking internal iteration, so deployment must apply the schema change before the substrate is enabled.
- Existing optional partition scheduling remains outside this slice. Its MySQL partition-key/primary-key constraints and default scheduling behavior were not redesigned here; that cleanup belongs to the downstream Command/Event state-machine work.
- Claim eligibility uses the persisted retry timestamp and existing terminal/in-flight states. Terminalization by retry budget and record expiry is performed by the token-bound failure transition; broad legacy scheduling/Locker removal is intentionally deferred.

# Conclusion

Pass for `runtime-jpa-atomic-claim-lease`. The private shared JPA substrate now provides atomic ownership fencing for both reliable Command and Event carriers, with real transaction/concurrency evidence and the remaining database-specific boundaries explicitly recorded for downstream integration.
