# Runtime And Analysis Boundaries

- Contract is a dependency-leaf published-language role; Domain owns invariants, Application owns use-case orchestration, Adapter maps protocols, and Start assembles runtime.
- Repository restores/accesses Aggregate roots and explicitly removes roots. Factory creates roots. The outer Command owns transaction and automatic Unit of Work stabilization; business code must not locate or flush Unit of Work.
- Mediator is a framework facade, not a business engine. Endpoint calls use `Mediator.endpoints`; Provider handlers and generated RPC Consumer remote handlers are local `EndpointHandler` implementations and are not called directly. Consumer business code constructs the published Request and uses `Mediator.endpoints.send/sendAsync`; a local anti-corruption language uses `Mediator.capabilities -> CapabilityHandler -> Mediator.endpoints`. Use only capabilities that the current machine catalog reports as installed and ready.
- Endpoint RPC is explicitly selected by stable non-blank `serviceId` plus non-empty selected `operationNames`. `ddd-endpoint-rpc` is the neutral ABI, `ddd-endpoint-rpc-http` is the unary HTTP/JSON backend, and `cap4k-ddd-endpoint-rpc-http-starter` owns assembly. The default route resolver is an assembly-owned static `serviceId -> base URI` map; timeout/auth/header customization stays in assembly and automatic retry is absent. OpenFeign, gRPC and discovery are not shipped. Direct HTTP is typically North-South and RPC is typically East-West, but traffic direction is not an identity.
- Reliable Command and persisted/delayed Domain Event behavior requires the corresponding provider. Registration joins the current transaction and must not force a provider-wide flush.
- Runtime transport consumes, parses, registers and dispatches external events. Integration Event payloads belong to the contract module; Application subscribers interpret typed facts, enforce idempotency, translate semantics and delegate state changes. Event direction does not bind a middleware; Spring YAML/runtime configuration still owns provider topology keyed by `eventName`.
- Endpoint contract declaration, Provider Handler-only code, generated RPC Consumer handlers and local `Mediator.endpoints` dispatch are non-entry evidence. A real typed Spring MVC `EndpointMvcBinding` registration is the direct HTTP Provider Actor detector; a real generated `EndpointRpcProviderBinding` registration is the RPC Provider Actor detector. Analyzer joins either to the independent Provider Handler by generated Request/operation identity. Protocol-specific relationships to Command can create default Flow roots, while relationships to Query remain raw Graph-only. HTTP and RPC registrations for one operation remain separate entry identities; Consumer proxies never add an entry. Without a real Provider binding detector, an Endpoint is not an Actor graph node or Flow root. Analyzer output proves only the structures and relations it observed. Raw graph, normalized design projection, and Aggregate Structure are independent facts: do not substitute one for another or treat `drawing_board_aggregate_elements.json` as Design JSON.
- `analysis.json` v2 exposes `graph`, `designProjection`, and `aggregateStructure` as partition-local facts. Read the partition requested by the operation, its own status/sources/freshness/diagnostics, and do not use the section-level status or another partition as proof of completeness.
- Default Flow is an entry-centered business causal projection from the raw graph. Conceptual entries are Actor, Event, or Time; current production detectors are Spring HTTP Controller methods, typed Spring MVC `EndpointMvcBinding` registrations, generated `EndpointRpcProviderBinding` registrations, inbound Integration Events with no upstream evidence, and Spring `@Scheduled` methods that directly send a Command. Endpoint HTTP/RPC Provider registrations mapped to Query remain Graph-only; only their Command relationships can form protocol-specific roots. It keeps concrete entry, Command, Domain Event, and Integration Event nodes; hides and contracts arbitrary-length Command/Event Handler and Entity Method paths; and excludes Query, Capability, and Validator from the default chain. A scheduled method that only sends Query, calls Capability, or performs technical logic does not form a Flow. Ordinary internal Command senders are not generic entries, and an arbitrary `*ToCommand` suffix is insufficient unless a real detector emits a relationship whose prefix matches the concrete source-node role; retired `commandsendermethod` evidence is rejected. Continuous evidence from one real entry stays in one Flow. Two independently evidenced roots stay as two Flows even when they share a downstream suffix; correlate them through `index.json`, stable entry identities, and shared visible nodes rather than automatic process stitching. Temporal detection is analysis evidence, not scheduler runtime, Job generation, cron/misfire/retry semantics, or process stitching. Pipeline `flow` is the only product entry.
- Analyzer evidence does not prove business intent, strategic correctness, transaction commit, delivery retry, or compensation.
- Existing evidence is fresh only when the snapshot proves matching project configuration and input identity; otherwise report `stale`, `unknown`, or `missing` and run the explicit planning task when needed.
